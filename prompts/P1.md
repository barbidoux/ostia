# P1 · Pipeline — phase brief

**Goal.** Scan a disk image end to end with a fake engine: inventory (hidden files, alternate data
streams), single hashed read and copy, content-based triage, recursive extraction under limits,
declarative signed verdict policy, medium verdict, JSON report, maximum scan time.
**Exit gate.** Every test in `tests/acceptance/p1/` green, unchanged; full scan of every disk-image
type with no USB hardware; P2 acceptance tests locked.

## Entry checks
- P0 gate ticked; `lock-p1` and `lock-common` tags exist; `ostia_lock.py verify --require-tags` passes.
- `python3 tools/lock/ostia_lock.py status` shows `p1` LOCKED. Run the p1 suite once and keep the list of
  failing tests: it is the phase's to-do list. Each package should turn some of them green.
- The owner confirmed the sudoers rule for `tools/dev/` scripts (images are loop-mounted).

## Order
WP-1.1 → WP-1.2 (policy) ‖ WP-1.3 (fixtures) → WP-1.4 → WP-1.5 ‖ WP-1.6 → WP-1.7, WP-1.8 → WP-1.9
→ WP-1.10 → WP-1.11 → WP-1.12 (lock P2). WP-1.3 and WP-1.6 can start right after WP-1.1.

## Package guidance

### WP-1.1 Domain model (`crates/core-domain`)
- Types: `Session`, `Medium`, `Device` (placeholder), `ObjectNode` (id, parent_id, origin, depth,
  path or offset, type, size, sha256, sha1), `Verdict`, `ObjectVerdict`, `MediumVerdict`, `EngineResult`
  (wrapping the Protobuf `AnalyzeResponse`). Pure Rust, no I/O.
- **Stop point 👤**: the worst-of ordering. The spec says MALICIOUS and UNSCANNABLE both block the medium
  but does not rank them. Propose `CLEAN < SUSPICIOUS < UNSCANNABLE < MALICIOUS` (a medium with both shows
  MALICIOUS, the stronger signal) in an ADR and get the owner's answer before coding the ordering.
- Property tests: worst-of is commutative, associative, idempotent, monotonic, independent of order;
  object tree invariants (parent exists, depth = parent depth + 1, no cycles, max depth enforced).

### WP-1.2 Verdict policy engine
- Policy file (TOML or JSON, decide in the ADR-09 follow-up) with a version, rules R1–R7 as data
  (conditions over engine results, hashes, heuristics flags), the EMBER thresholds placeholders, K for
  K-of-N, the hooks for D1 and D2, and mode semantics (compliant, selective, scan-only).
- Loader: verify the Ed25519 detached signature over the exact bytes **before** parsing; reject unknown
  keys; reject unsigned, altered, or signed-by-unknown-key policies with distinct errors.
- Evaluation: first matching rule wins, rule id recorded in the verdict. R1 (any failure/timeout/limit or
  unsupported risky type) must win over everything; R3 (known-good) never beats R1 or R2.
- Table-driven tests: one row per rule and one per precedence pair; these tables are what mutation testing
  (P3) will score, so make them exhaustive now.

### WP-1.3 Disk-image fixture generator (`tests/fixtures/`, Python)
- API used by the locked tests (`build_image(fs, files, ...)` or whatever `common/` calls): honour that
  signature exactly — read `tests/acceptance/common/` first.
- FAT12/16/32 with `mkfs.vfat` + `mtools` (no root), ext2/3/4 with `mkfs.ext4 -d <dir>` (no root),
  exFAT and NTFS need a mount to populate: FUSE (`ntfs-3g`, `exfat-fuse`) where available, otherwise
  `tools/dev/loopmount.sh rw-image` on the image file under `target/fixtures/` (never a device).
  NTFS alternate data streams: mount with `ntfs-3g -o streams_interface=xattr` and `setfattr -n user.<stream>`,
  or write them with `ntfscp -N <stream>` (check the option in `man ntfscp` on the target Debian).
- Planted content is declared in the test (path, bytes or generator, attributes: hidden, ADS, trapped
  names with control/bidi characters, double extensions). The generator writes a manifest; its self-tests
  re-mount every image and compare with the manifest.
- Keep images small (a few MiB) and cache them under `target/fixtures/` keyed by a hash of the spec.

### WP-1.4 Development mount layer
- Detect the file system by probing (in a worker, or with `blkid` run by the dev helper — the orchestrator
  must not parse superblocks itself; SEC-05). Mount read-only through `tools/dev/loopmount.sh`.
  This dev layer is replaced by the privileged helper in P4; keep it behind a `MediaAccess` trait.
- Unsupported file system → exit 4 with a clear message and a report saying why.

### WP-1.5 Inventory and single read
- Walk the mounted tree without following symlinks (record them as objects of their own), list hidden
  files, alternate data streams and extended attributes. ADS are visible as xattrs only through `ntfs-3g`
  with `streams_interface=xattr`; the kernel `ntfs3` driver does not expose them that way, so the mount layer
  must use ntfs-3g for NTFS (record this in an ADR; check the behaviour on the target kernel). Read each object once: stream → SHA-256 + SHA-1 → copy into the workspace (plain directory
  in P1; encrypted in P4). The analysed copy is the only one used afterwards (SEC-10).
- Test the TOCTOU property: change the source after the read; the report and the copy keep the read content.
- ADS and xattrs are scanned but flagged never-transferable (DEEP-05).

### WP-1.6 Worker host v0
- Spawn the worker with the object as fd 3 (read-only), framed request on stdin, one framed response on
  stdout, stderr captured with a size cap. Timeout → kill the process group → `TIMEOUT`; crash or garbage →
  `ERROR`; host keeps running (NFR-05). No sandbox yet (P2), but keep the spawn behind the `sandbox` crate API.
- Tests: echo worker round-trip, sleeping worker → TIMEOUT, crashing worker → ERROR, huge stderr capped.

### WP-1.7 Triage worker (Rust)
- Content-based type identification (`infer` crate or a small magic table — check licences), extension
  mismatch and double-extension flags. A structural test asserts the orchestrator crate has no dependency on
  type-detection or archive crates (inspect `cargo metadata`), proving SEC-05 mechanically.

### WP-1.8 / WP-1.9 Extraction worker
- Formats part 1: zip, tar, gz; part 2: 7z, rar, cab, iso, msi. Prefer pure-Rust crates (`zip`, `tar`,
  `flate2`, `sevenz-rust`, `cab`, `cfb`/`msi`) — check each licence; for rar, `unrar` is non-free:
  stop and ask 👤 (options: `compress-tools`/libarchive in the sandbox as a separate process, or rar listing only).
- Limits enforced while streaming, never after: depth, per-entry and cumulative compression ratio, total
  bytes written, entry count, path length; entry names sanitised (no `..`, absolute paths, NUL, devices);
  encrypted entries reported as password-protected (FR-07 is P7). Any breach → UNSCANNABLE for the
  archive object, with the limit named in the report.
- Children are returned as new objects (origin EXTRACTED) and go through triage and the cascade.
- Tests generate archives at test time (Python `zipfile`, `tarfile`, `py7zr`, `pycdlib` for iso), including
  bombs of a few KiB that expand far beyond the limits.

### WP-1.10 Orchestrator pipeline
- Session lifecycle, bounded queues (`tokio::sync::mpsc` with capacity), dispatch of each object to the
  applicable engines (here the fake engine via `--dev-engine`), policy evaluation per object then medium,
  JSON report validated against `schemas/report.schema.json` in the tests.
- Reproducibility (NFR-07): same image, same fake-engine config and same policy → identical verdicts
  (ignore timestamps and session ids).

### WP-1.11 Maximum scan time
- Budget from policy or CLI; on expiry apply the configured action (e.g. mark remaining objects
  UNSCANNABLE and block, or stop) and record it in the report. Fake clock in unit tests; in acceptance
  tests margins are wide (budget ≪ fake-engine delay).

### WP-1.12 Lock: P2 acceptance tests → `/phase-lock P2`
P2 tests must cover: sandbox (SEC-01 to SEC-04: a probe worker trying network, writes outside its tmpfs,
reading the workspace or another medium's files fails; memory hog, fork bomb, disk filler each give
UNSCANNABLE and the scan completes — NFR-04, NFR-05), EMBER bundle (unsigned, tampered, wrong dimension
2,568 refused — NFR-17), EMBER scoring through the CLI on clean files (CLEAN) and on a test bundle with
lowered thresholds (SUSPICIOUS and MALICIOUS paths, R4/R5), truncated or corrupted PE → UNSCANNABLE,
report carries model hash and thresholds (NFR-17) and top factors with labels for non-CLEAN verdicts
(NFR-12), reproducibility (NFR-07). Latency (NFR-02) is a benchmark, verified in WP-2.8: list it under
"verified elsewhere". Clean test binaries are generated or taken from the Debian system at test time
(never committed); no malware.
Contracts to add first: `ostia scan --model-bundle <dir>`, sandbox profile options if needed, report fields
for model hash, thresholds and factors.

## Owner checkpoints in P1

gate. After P1 the plan asks for a first pace measurement: sessions per package, median per size.
