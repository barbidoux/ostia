# P4 · USB and media — phase brief

**Goal.** Move from disk images to real devices on the dedicated Debian bench: USB defence
(USBGuard policy, driver allowlist, session-long monitoring, fingerprints), the privileged mount and
raw-read helper, the encrypted ephemeral workspace, verified transfer and the signed manifest,
service accounts and systemd hardening.
**Exit gate.** `tests/acceptance/p4/` green on the bench, unchanged; full journey with a real drive;
every emulated malicious device blocked or flagged; P5 tests locked.

## Entry checks
- P3 gate ticked, `lock-p4` tag, verify passes.
- 👤 The Debian bench exists: Debian stable, kernel with `dummy_hcd`, `libcomposite`/configfs, USBGuard,
  `cryptsetup`, a spare USB port and a few cheap test drives that may be wiped, labelled "OSTIA TEST".
  The repository is cloned there; Claude Code runs there or the owner runs `just test-bench` and pastes output.
- `OSTIA_BENCH_DEVICE` (owner-set) names the only real device tests may format. The guard hook blocks any
  command writing to `/dev/sd*` directly: bench scripts read the device from that variable and check its
  serial against `bench.toml` before touching it.

## Package guidance

### WP-4.1 Device test bench
- `tests/fixtures/gadgets/`: configfs scripts (`/sys/kernel/config/usb_gadget/<name>`) bound to `dummy_udc`
  for: plain storage (mass_storage function backed by an image file), HID + storage composite, class liar
  (storage class in the interface descriptor but an extra HID/CDC interface, or vendor-specific claiming
  storage), delayed re-enumeration (unbind/rebind after N seconds with a different descriptor), network
  adapter (ECM/RNDIS). Each fixture tears down cleanly even after a failed test.
- Self-tests: each gadget enumerates as designed (`lsusb -v` / sysfs descriptors compared with the spec).
- Gadget setup needs root: one script under `tools/dev/`, argument-validated, owner-approved in sudoers 👤.

### WP-4.2 USB sentinel (`crates/usb-sentinel`)
- Listen to udev (netlink, `udev` crate) for add/remove/change; read descriptors from sysfs only (no
  parsing of device-provided data outside careful, fuzzed code; strings are untrusted).
- Generate the USBGuard policy: external ports `allow with-interface equals { 08:*:* }` (exactly one
  mass-storage interface — check how USBGuard treats `equals` with a single interface type across several
  interfaces), internal ports by exact `id`, `serial`, `via-port`, `with-interface` and `hash`; default block.
  Apply it with `usbguard` IPC or rules file + daemon reload.
- Fingerprint (USB-05): VID/PID, serial, bcdDevice, strings, interface list, descriptor hash — logged as an
  event (P6 will make it OCSF).

### WP-4.3 Driver allowlist on external ports
- Disable kernel auto-probing on external ports (`/sys/bus/usb/drivers_autoprobe` per bus or `authorized_default=0`
  on the external hubs), then authorise interfaces individually (`interface authorized`), binding only
  `usb-storage` or `uas`. HID, CDC, network, wireless, audio and video drivers never bind there.
- The class-liar gadget gets no driver and is reported (finding + D1).

### WP-4.4 Session-long monitoring
- During a session, any re-enumeration, new interface or configuration change → abort the session, discard
  results, raise a USB alert (D1). Anomaly heuristics (USB-06): several configurations, vendor-specific
  interfaces, inconsistent strings, unusual subclass/protocol, capacity inconsistent with the model.

### WP-4.5 Privileged helper (`crates/media`, binary `ostia-media-helper`)
- Tiny, synchronous, no shell, no `PATH`; talks to `os-media` over a Unix socket with a fixed request enum
  (mount ro, unmount, open raw read-only, format output, write marker). Strict validation: device must be a
  whole disk or partition currently authorised by the sentinel, mount point inside a fixed directory, file
  system from a fixed list, options fixed `ro,noexec,nosuid,nodev` (+ `nosymfollow` if available).
- Mount in a dedicated mount namespace shared with the orchestrator's reader only.
- Block unsupported file-system kernel modules (`/etc/modprobe.d/ostia-blacklist.conf` with `install <fs> /bin/false`).
- Fuzz the request parser (cargo-fuzz target).
- ADR for the helper's privilege model (capabilities `CAP_SYS_ADMIN` only for mount, or setuid-less service).

### WP-4.6 Encrypted ephemeral workspace
- dm-crypt plain or LUKS2 on a file-backed loop or a dedicated partition, key from `getrandom` held only in
  memory (zeroized), destroyed at session end (crypto erase) — and after a crash the key never existed on
  disk, so the volume is unreadable. Test both paths. tmpfs alternative for small media: decide in an ADR.

### WP-4.7 Output medium
- Controlled-medium marker written by the kiosk (signed, contains a kiosk id and medium serial), formatting
  by the helper, copy of the **scanned copies** from the workspace (never re-reading the input), SHA-256
  verification after copy (read back after flushing caches: `O_DIRECT` or drop the page cache for that device).
- Refusals: the input device as output (compare serial, path and fingerprint), unknown output device.

### WP-4.8 Signed transfer manifest
- Canonical JSON (JCS, RFC 8785 — use a tested crate or implement against the RFC test vectors), Ed25519
  signature, fields per CTR-05: kiosk id, timestamp, files with SHA-256 and verdict, engine and policy versions.
  `schemas/transfer-manifest.schema.json`. Stable across runs (test byte equality).

### WP-4.9 Service accounts and systemd units
- Accounts `os-media`, `os-orch`, `os-worker`, `os-engine`, `os-enrich`, `os-journal`, `os-api`, `os-kiosk`,
  `os-update`. Units with `NoNewPrivileges=yes`, `ProtectSystem=strict`, `ProtectHome=yes`, `PrivateTmp=yes`,
  `PrivateDevices=yes` (except media), `RestrictAddressFamilies`, `SystemCallFilter=@system-service`,
  `CapabilityBoundingSet=` minimal, `MemoryDenyWriteExecute=yes` where possible, `Delegate=yes` for the
  orchestrator slice (cgroups). Gate each unit with `systemd-analyze security <unit>` thresholds in tests.
- Workspace mounted `noexec` (SEC-12) and tested by trying to execute a copied file.

### WP-4.10 End to end on real drives
- Scripted journey: insert (or gadget-plug) a FAT, exFAT and NTFS drive with planted content, scan,
  select, transfer to a controlled output drive, verify manifest. A short manual protocol in
  `docs/bench/manual-protocol.md` for the owner 👤 (physical insertion, unplug mid-scan).

### WP-4.11 Lock: P5 acceptance tests → `/phase-lock P5`
P5 tests (bench and image-based) must cover: deep-scan fixtures with markers at declared offsets in MBR/VBR
boot code, partition gaps, unallocated blocks, slack, deleted entries, an extra hidden partition; raw
descriptor read-only and confined (DEEP-01); layout maps match (DEEP-02) and a malformed partition table
gives a finding, not a crash; markers in boot code and gaps found in standard mode (DEEP-03, FR-24); carved PE
re-enters the cascade with origin CARVED; unallocated/slack/deleted markers found only in deep mode (DEEP-04,
DEEP-07); time estimate within tolerance and budget stop with coverage reported (NFR-18); entropy region
reported (DEEP-06); D2 alert by default, block when configured (DEEP-08); logs and report hold offsets and
hashes only, never marker content (DEEP-09) — assert the marker bytes appear nowhere in logs, report or
events. Markers are random per test run (so a test cannot pass by hard-coding them) and harmless.
