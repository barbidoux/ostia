# P5 · Deep scan — phase brief

**Goal.** Read the raw device to find payloads hidden outside files: boot code, partition gaps,
unallocated space, slack, deleted entries, hidden partitions; carve objects back into the cascade;
estimate time and respect a budget; never keep or log content.
**Exit gate.** `tests/acceptance/p5/` green, unchanged; every planted marker found on every image type,
within the time estimate, with no content in logs; P6 tests locked.

## Entry checks
- P4 gate ticked, `lock-p5` tag, verify passes. Bench available for the device-level tests.
- The Sleuth Kit available in the worker image (`mmls`, `fsstat`, `fls`, `blkls`, `icat`, `istat`).
  TSK is CPL-1.0/IBM PL and GPL parts: run its CLI tools as separate processes inside the sandbox, never link
  (check the licence of each tool used and record it in an ADR) 👤.

## Order
WP-5.1 → WP-5.2 → WP-5.3 → WP-5.4 → WP-5.5 → (WP-5.6 ‖ WP-5.7) → WP-5.8 (lock P6).

## Package guidance

### WP-5.1 Deep-scan fixtures
- Extend the image generator: write markers at exact byte offsets in the MBR boot code (bytes 0–445),
  VBR boot code, gaps between partitions (and before the first one), unallocated clusters (write then
  delete, or write directly to free clusters computed from the FS map), file slack (after EOF inside the last
  cluster), deleted directory entries, and an extra partition not referenced by the visible FS.
- Markers: random per run, harmless, unique (e.g. 32 random bytes framed by a fixed tag), some shaped as a
  tiny valid PE/ELF/ZIP so carving can find them. The manifest lists offsets and kinds; self-tests read the
  raw image at each offset.

### WP-5.2 Raw read path
- The helper opens the block device `O_RDONLY` and passes only the descriptor over SCM_RIGHTS to the deep-scan
  worker's sandbox. The worker cannot open other devices because its mount namespace has only a minimal
  `--dev` (no block devices); seccomp cannot filter by path, so it only restricts syscalls (no `ioctl` beyond
  the read-only ones needed, no `write` on that descriptor). The helper also sets `BLKROSET` on the device for
  the session as extra defence.

### WP-5.3 Device mapper
- In the sandbox, run TSK on the descriptor (`/proc/self/fd/3`): partition table (`mmls`), per-partition FS
  (`fsstat`), allocated/unallocated runs (`blkls -l`/`-e`, `blkcalc`), yielding a layout map: partitions,
  extents, gaps, totals. Malformed tables → finding + partial map, never a crash (fuzz the map parser).

### WP-5.4 Boot code and gaps
- Always in standard mode: YARA-X over boot code and gaps; signature carving (PE `MZ`+`PE\0\0` with header
  sanity, ELF, ZIP local headers + central directory, scripts by shebang) with size limits. Carved objects get
  origin CARVED (or BOOT_CODE) and an offset, go through the normal cascade, and are wiped with the workspace.

### WP-5.5 Deep mode
- Unallocated blocks (`blkls`), slack (`fls` + `istat` to compute slack ranges, or `blkls -s`), deleted
  entries (`fls -d` then `icat` with care). Mode chosen by policy, device size threshold, or administrator
  request (DEEP-07). Standard-mode results never include deep-only areas (test).

### WP-5.6 Time estimate and budget
- Measure read throughput on the first MiBs, estimate total from the layout map, update during the scan.
  Budget expiry stops cleanly and reports coverage (bytes and areas covered vs total).
  Large sparse images in tests (several GiB, mostly holes) keep CI fast.

### WP-5.7 Entropy map, HIDDEN_PAYLOAD, privacy
- Entropy per block (e.g. 4 KiB) over unallocated areas; contiguous high-entropy regions above a size threshold
  reported as possible encrypted containers (DEEP-06).
- Executable content outside files → HIDDEN_PAYLOAD finding → D2 (alert by default, block when the policy says
  so — 👤 the default is an open question in the spec).
- Privacy (DEEP-09): store and log only offset, type, hash, rule; tests assert marker bytes never appear in
  logs, events, report or any file outside the workspace.

### WP-5.8 Lock: P6 acceptance tests → `/phase-lock P6`
P6 tests must cover: every emitted event validates against the pinned OCSF schema version (LOG-01) — vendor
the schema files under `schemas/ocsf/<version>/`; two separate logs, events and transfers (LOG-01); edited,
deleted, reordered, inserted entries each detected and a clean log verifies (LOG-02, LOG-03) via
`ostia log verify`; rotation keeps the chain valid across files and notifies, scanning continues (LOG-04);
logging service unprivileged (LOG-05, bench or systemd-analyze based); forwarding with mutual TLS 1.3,
wrong certificate refused, at-least-once with de-duplication (LOG-06); collector cut then restored: no loss,
no reordering (LOG-07); signed manual export verifies offline (LOG-08); no file content in any event and
stable pseudonymised paths (LOG-09); FR-19 end to end (a scan's transfer and events reach the fake collector).
Contracts first: platform API (`POST /v1/kiosks/{id}/events:batch`, heartbeat) as OpenAPI in
`schemas/platform-api.yaml`, `ostia log verify|export` CLI, event envelope.
