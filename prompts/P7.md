# P7 · Kiosk UI — phase brief

**Goal.** Give the kiosk its screens and its administration: OpenAPI contract, local API with per-boot
token and progress stream, administrator authentication and roles, kiosk shell lockdown, user journeys
(device check, progress, results, selection, quarantine, transfer, report), password-protected archives,
administrator screens, English and French.
**Exit gate.** `tests/acceptance/p7/` green, unchanged; user and administrator journeys green in Playwright;
P8 tests locked.

## Entry checks
- P6 gate ticked, `lock-p7` tag, verify passes. Node.js ≥ 20 and pnpm in the dev container; Playwright
  browsers installed by the owner if the network policy requires it 👤.

## Order
WP-7.1 → WP-7.2 → (WP-7.3 ‖ WP-7.4) → WP-7.5 (after 7.4) → WP-7.6 → WP-7.7; WP-7.8 (after 7.3);
WP-7.9 (after 7.6) → WP-7.10 (lock P8).

## Package guidance

### WP-7.1 OpenAPI contract
- Hand-written OpenAPI 3.1 (`schemas/local-api.yaml`): sessions, devices, objects tree, verdict filters,
  selection, quarantine, transfer, report export, archive password submission, admin auth, policy/profile,
  engines and health, update import, logs, mode. Progress as Server-Sent Events (`text/event-stream`) with
  ordered `id`s. Error model shared by every endpoint.
- ADR: UI framework (Svelte proposed for size and simplicity) and the build toolchain (Vite), all offline.
- Contract tests generated from the schema (schemathesis) must fail against an empty server first.
- Acceptance journeys are Python pytest-playwright tests (`tests/acceptance/`); TypeScript tests (Vitest) cover
  components and units.

### WP-7.2 Local API (`crates/api`, axum)
- Listen on a Unix socket (preferred) or 127.0.0.1 only; refuse to start otherwise. Token from `getrandom`
  at each start, handed to the kiosk shell through a file readable only by `os-kiosk`; constant-time compare.
- SSE stream fed by orchestrator events, back-pressure bounded; reconnection with `Last-Event-ID`.

### WP-7.3 Administrator authentication
- Argon2id (`argon2` crate) with parameters documented in an ADR (memory ≥ 64 MiB on the target);
  lockout after N failures for T minutes (both in policy); roles admin and super-admin; super-admin-only
  actions: manage admin accounts, switch selective mode, change enrichment settings (P8).
- Sessions short-lived, re-authentication for sensitive actions, every action logged (OCSF).

### WP-7.4 Kiosk shell
- `cage` (Wayland kiosk compositor) running Chromium with `--kiosk`, an enterprise policy JSON
  (`/etc/chromium/policies/managed/ostia.json`): `URLAllowlist` only the local origin, `URLBlocklist` `*`,
  `DeveloperToolsAvailability: 2`, `DownloadRestrictions: 3`, `PrintingEnabled: false`, no extensions,
  incognito disabled, keyboard shortcuts limited (some need compositor-level filtering).
- Strict CSP header from the API: `default-src 'self'; script-src 'self'; style-src 'self'; connect-src 'self';
  object-src 'none'; frame-ancestors 'none'; base-uri 'none'`.
- Tests with pytest-playwright on Chromium with the same flags. Managed policies are read only from
  `/etc/chromium/policies/managed/` (or `/etc/opt/chrome/policies/managed/` for Chrome), which needs root:
  run these tests in the dev container (or the kiosk image) where the policy file is installed at build time.

### WP-7.5 / WP-7.6 User journeys
- Home → insert → device check (USB explanations, USB-07, from structured findings, translated) → progress →
  results tree with filters and per-object explanations (engines, rules, scores, factors) → selection (only CLEAN
  in compliant mode; business-format allowlist, FR-11) → quarantine (FR-12) → transfer → report shown and exported
  (FR-16).
- File names: always text nodes; visible escapes for control and bidi characters (U+202A–202E, U+2066–2069,
  U+200E/F) and a flag (UI-05). Test with the trapped names from the P1 fixtures.

### WP-7.7 Password-protected archives (FR-07)
- The password is sent to a dedicated extraction worker in a fresh sandbox; never logged, never stored, zeroized;
  extracted children go through the full cascade. Without the password: UNSCANNABLE, nothing transfers.

### WP-7.8 Administrator screens
- Policy and profiles (signed policy import, never in-browser edits of signed content), engines and certification
  status, health (ENG-07), update bundle import (wired fully in P9), logs view and export, scan-only mode (FR-21:
  a test asserts no write to any block device during a scan-only session).

### WP-7.9 Languages, touch, readability
- Catalogues `en` and `fr` with identical keys (test), no hard-coded strings (lint rule), journeys at kiosk
  resolution with touch emulation in Playwright.

### WP-7.10 Lock: P8 acceptance tests → `/phase-lock P8`
P8 tests must cover, **only against the fake provider and recorded VirusTotal responses**: provider interface
contract reused for every provider (ENR-01); each upload mode allows exactly what it should — `disabled` (hash only,
no upload button), `admin_approval` (upload only after an administrator approves), `user_choice` — and the deny
list holds in every mode; no profile means regulated defaults; settings changes need a super-administrator and
are logged (ENR-02, ENR-04, ENR-13); sharing warning shown before any upload and Private Scanning used when
licensed, ZIP password only with Private Scanning (ENR-03, ENR-10); "not found" and zero detections never
downgrade, ≥ N detections upgrade to MALICIOUS (ENR-05, E1); late detection on a transferred file raises a
post-transfer alert with the manifest id (ENR-06); quota scheduler respects limits and serves UNSCANNABLE first
(ENR-07); key encrypted at rest, never logged or shown again, absent in relay mode (ENR-08, SEC-14); every request
logged with what, who, approver, result (ENR-11); offline bundles signed both ways and tampering refused (ENR-12,
CTR-07 schema published); relay mode never holds the key; direct mode reaches only the provider API and only in a
profile that allows it (NFR-08); local verdicts never wait on enrichment and failures never block a session
(NFR-19); dialog content (UI-09); FR-25 end to end with the fake provider.
Contracts first: provider trait docs, `schemas/enrichment-bundle.schema.json` (request and result), CLI
`ostia-enrich` (analyst side), local API endpoints for the dialog.
