# P9 · Release 1.0 — phase brief

**Goal.** Make Ostia updatable, hardened, measured and documented: TUF repository and updater with
anti-rollback and atomic apply, boot-time integrity, signed reproducible release with SBOM, automated
hardening checklist, performance on the reference medium, evaluation bench, documentation, release 1.0.
**Exit gate.** `tests/acceptance/p9/` green, unchanged; traceability matrix shows 100 % of MUST requirements
green; reference medium scanned in under 10 minutes in standard mode; 1.0 tagged and published by the owner.

## Package guidance

### WP-9.1 TUF repository tooling
- `tuftool` (awslabs) to create and sign the repository: root, targets, snapshot, timestamp, and one delegated
  targets role per engine (`engines/<id>/*` paths) plus roles for models, rules, policy, software.
- Root ceremony documented in `docs/release/root-ceremony.md`: offline keys, M-of-N threshold, rotation
  procedure 👤 (the owner and co-holders perform it; the agent never holds real keys). Tests use throwaway keys.
- Test: an engine key cannot sign another engine's targets; root rotation accepted with threshold signatures,
  refused below threshold.

### WP-9.2 Updater (`crates/updater`, `tough`)
- Offline repository on admin media; verify with `tough` (expiry checks with a trusted time source decision —
  offline kiosks have unreliable clocks: ADR 👤), anti-rollback per component (persisted highest version),
  atomic apply via A/B release directories and a symlink switch (`renameat2` exchange or atomic symlink replace),
  health check after switch, automatic return to the previous release on failure (UPD-04).

### WP-9.3 Boot-time integrity
- A manifest of hashes for binaries, policies, configuration (signed), checked by a oneshot unit before the
  services start; failure → safe state (no scanning, clear screen message, logged reason). dm-verity or IMA are
  stronger options for integrators: document them in the hardening guide.

### WP-9.4 Release pipeline
- Signed artefacts (Ed25519 or Sigstore keyless if the owner prefers 👤), CycloneDX SBOMs (Rust and Python),
  SHA-256 sums; reproducible-build check: two builds of the same commit in clean containers with
  `SOURCE_DATE_EPOCH`, `--remap-path-prefix`, locked dependencies, then compare (report differences; UPD-08 is a
  SHOULD). The pipeline fails without an SBOM. Publishing is the owner's act.

### WP-9.5 Hardening checklist (ANSSI-BP-028 subset) and integrator guide
- Script checking the kiosk image: services and accounts, sysctl, kernel module blocklist, mount options, systemd
  unit exposure scores, USBGuard active, no listening sockets except loopback/Unix, firewall default-deny.
  Test: it fails on a deliberately weakened image (container or VM image built in the test).

### WP-9.6 Performance bench
- Reference medium per the owner's definition, standard mode, recommended configuration: total under 10 minutes
  (NFR-01), ready within 60 s of service start with antivirus databases loaded (NFR-03). Profile and tune worker
  pools, cascade order, clamd settings. Record results in `docs/bench/`.

### WP-9.7 Evaluation bench (isolated, opt-in, outside CI)
- Separate repository or directory excluded from CI and from the default build; runs only on an isolated machine
  owned by the owner, from an encrypted corpus he provides 👤. The agent writes the harness and report generator
  against a **pinned corpus manifest** (hashes only), and tests them on synthetic data; it never downloads,
  handles or stores real malware. Report: per engine and fused detection rate, FPR on the clean corpus,
  reproducible from the manifest.

### WP-9.8 Documentation
- User, administrator, integrator, deployment profiles (regulated vs community), engine-pack authoring (manifest,
  adapters, conformance kit), enrichment (licence warning ENR-09), compliance statement ("ANSSI-PG-076 compliance
  targeted, not certified"). A script checks that every configuration key in the schemas is documented.

### WP-9.9 Release 1.0
- `just trace --gate all`: 100 % of MUST requirements green; `/phase-gate P9`; CHANGELOG; release notes draft.
- 👤 The owner tags `v1.0.0`, signs and publishes.
