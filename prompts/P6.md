# P6 · Logging — phase brief

**Goal.** Make every event provable and forwardable: OCSF events, two hash-chained logs with signed
checkpoints, rotation, an unprivileged journal service, a persistent queue with mutual-TLS forwarding to a
(fake) central platform, signed manual export, path pseudonymisation.
**Exit gate.** `tests/acceptance/p6/` green, unchanged; tampering detected; full replay to the fake
collector with no loss; P7 tests locked. P6 only needs P1's domain events: a second contributor could
run it in parallel with P2–P5.

## Entry checks
- P5 gate ticked (or the owner opened P6 in parallel 👤), `lock-p6` tag, verify passes.

## Order
WP-6.1 → (WP-6.2 → WP-6.3) ‖ WP-6.4 → WP-6.5 (after 6.3, 6.4) → WP-6.6 (after 6.3) → WP-6.7 (lock P7).

## Package guidance

### WP-6.1 OCSF event model (`crates/journal`)
- Pin one OCSF schema version and vendor the needed class and object JSON under `schemas/ocsf/<version>/`
  (Apache-2.0; keep the licence file). Classes: Peripheral Activity (USB events), Scan Activity (sessions),
  Detection Finding (non-CLEAN verdicts, USB and hidden-payload findings), File System Activity (transfers),
  plus authentication/account change classes for administrator actions — confirm class ids against the pinned
  schema, never from memory.
- Validation in tests with `jsonschema` (Python) against generated schemas, for every event the kiosk emits.
- Kiosk-specific fields go in `unmapped` or an Ostia extension, documented.

### WP-6.2 Hash-chained store
- Append-only files of JSON lines: each entry = event + `seq` + `prev_hash` (SHA-256 of the previous entry's
  canonical bytes) + `hash`. Signed checkpoints (Ed25519 over `seq`, `hash`, time) every N entries or T minutes
  and at rotation. `ostia log verify <dir>` detects edits, deletions, reordering, insertion, truncation of the
  tail after the last checkpoint (report it as such), and a forged checkpoint.
- fsync policy documented (durability vs throughput), crash mid-write leaves a detectable, recoverable state.

### WP-6.3 Two logs, rotation, unprivileged service
- Separate `events` and `transfers` logs. Rotation at capacity: checkpoint, new file whose first entry chains
  to the previous file's last hash, administrator notification event; the kiosk keeps scanning (LOG-04).
- `os-journal` account; the orchestrator sends events over a Unix socket; the journal never reads the workspace.

### WP-6.4 Fake collector
- Implements the platform contract (`schemas/platform-api.yaml`): `POST /v1/kiosks/{id}/events:batch`
  (ack up to the highest contiguous seq, duplicate handling by event id + seq), `heartbeat`; mutual TLS with a
  test CA generated at test time (Python `trustme` or `cryptography` for the fake collector, `rcgen` on the Rust
  side); scripted outages and slow responses. Contract tests for the collector
  itself.

### WP-6.5 Forwarder
- Persistent on-disk queue (append-only segment files or SQLite WAL), at-least-once delivery, retries with
  backoff and jitter, ordering preserved, de-duplication on the collector side by id + seq, TLS 1.3 only with
  `rustls`, client certificate per kiosk, server pinned to the configured CA. Cut-and-restore test: no loss,
  no reordering; wrong certificate refused both ways.

### WP-6.6 Signed export and pseudonymisation
- `ostia log export --to <admin medium>`: log files + checkpoints + a signed export manifest; verifiable offline
  by `ostia log verify --export`.
- Pseudonymisation (LOG-09): HMAC-SHA-256 with a per-kiosk secret over path components, stable per kiosk,
  irreversible without the secret; configuration switch. A test greps every event for planted file content and
  original paths when pseudonymisation is on.

### WP-6.7 Lock: P7 acceptance tests → `/phase-lock P7`
P7 tests must cover: OpenAPI contract (`ui/openapi.yaml` or `schemas/local-api.yaml`) — schemathesis runs against
the server (UI-01, UI-02); API reachable only on the Unix socket or 127.0.0.1, invalid or missing token refused,
token changes at restart (UI-01); progress events arrive in order (UI-02); Argon2id hashes, lockout after N
failures, administrator cannot manage administrator accounts, super-administrator can (FR-17, UI-07); kiosk
browser cannot leave the page or open devtools, other origins blocked, inline scripts refused (UI-03, UI-04 —
pytest-playwright against Chromium with the real flags and managed policies, run in the dev container where the
policy file can be installed under `/etc/chromium/policies/managed/`); user journey: rejected device explained (USB-07), results
filter by verdict, explanations per object (FR-16); only CLEAN files selectable in compliant mode, business-format
allowlist enforced, quarantine (FR-11, FR-12); trapped file names escaped and flagged (UI-05); password-protected
archive: nothing transfers without the password, contents scanned with it (FR-07); scan-only mode never writes
to any medium (FR-21); policy change requires the right role and is logged; engine health visible (ENG-07);
English and French catalogues complete (UI-08, NFR-16); no remote administration listener (UI-06: no socket bound
on non-loopback interfaces, checked with `ss`).

## Owner checkpoints in P6
